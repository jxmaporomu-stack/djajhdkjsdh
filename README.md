# 통합 디스코드 봇 (자판기 + 출퇴근 + LTC 슬롯)

한 개의 `index.js`와 **하나의 Discord 봇 토큰**으로 두 프로젝트가 실행됩니다.

## 구성
- `index.js`: 자판기/충전/재고/라이센스/출퇴근 및 공통 Discord 클라이언트
- `admin.js`: 서버 주인 전용 관리 패널
- `db.js`: 통합 SQLite 데이터베이스
- `slot.js`: Litecoin TXID 결제, 기간제 채널 슬롯, 연장, 만료 삭제, 핑 제한
- `config.example.json`: 슬롯 전용 설정 예제

## 설치 및 실행
1. Node.js **20 이상** 설치
2. `npm install`
3. `.env.example`을 `.env`로 복사하고 `TOKEN`, `MASTER_ID` 등 설정
4. 자판기만 쓸 때는 `ENABLE_SLOTS=false`
5. 슬롯을 사용할 때는 `ENABLE_SLOTS=true`, `config.example.json`을 `config.json`으로 복사 후 실제 서버 ID, LTC 주소, 카테고리 ID 입력 (DATABASE_URL/PG_SSL 불필요)
6. `npm start` (검사: `npm run check`)

## 라이센스 등급
- **일반**: 자판기 + 출퇴근 사용.
- **프리미엄**: 자판기 + 출퇴근 + 슬롯 사용. 슬롯 명령과 결제 확인, 채널 생성은 서버의 프리미엄 라이센스가 유효한 경우에만 실행됩니다.
- 봇 판매자는 `/라이센스생성 기간:30 등급:프리미엄`으로 프리미엄 키를 만들고, 서버 주인은 `/라이센스등록`으로 등록합니다. 키 자체의 구매/결제 자동화는 포함하지 않습니다.
- 기존 발급 키는 **일반** 등급으로 유지되고, 프리미엄은 별도 만료일로 연장됩니다. `FREE_GUILD_IDS`는 자판기 라이센스만 면제하며 슬롯은 면제하지 않습니다.
- 만료돼도 기존 슬롯에 대한 자동 만료/정리 작업은 계속 돌아갑니다.

## 재고 추가 전용 로그
- `/관리` → **재고 로그 채널** → 채널 지정. 재고 추가는 `/재고추가` 및 관리자 패널 양쪽에서 기록됩니다.
- 로그: 상품 번호·이름, 상품 가격, 추가 수량, 추가 후 재고, 담당 관리자, 시각. 실제 재고 내용(코드/계정 정보)은 유출 방지를 위해 게시하지 않습니다.
- SQLite에 `stock_add_logs` 감사 기록을 함께 남깁니다. 기존 DB에 새 컬럼과 테이블이 자동 추가됩니다.

## 명령어
- 자판기: `/관리`, `/패널`, `/상품추가`, `/상품수정`, `/상품목록`, `/상품삭제`, `/재고추가`, `/잔액지급`, `/설정`, `/라이센스등록`, `/라이센스확인`, `/라이센스생성`, `/라이센스목록`
- 출퇴근: `/출퇴근패널`, `/출퇴근기록`
- 슬롯(설정된 서버): `/슬롯상점`, `/슬롯구매`, `/txid`, `/슬롯핑`, `/슬롯정보`, `/슬롯연장`, `/슬롯카테고리설정`, `/슬롯삭제`

## 데이터베이스와 배포
- 자판기 데이터: 기존 `data.db` SQLite를 그대로 사용. 기존 DB가 있다면 보존한 채 같은 경로로 마운트하세요. Railway에서는 `DB_PATH=/data/data.db`와 **영구 볼륨** 권장.
- 슬롯 데이터: 자판기와 동일한 SQLite `DB_PATH` 파일을 사용합니다. 슬롯 테이블은 봇 시작 시 자동 생성됩니다.
- 이전 PostgreSQL에 저장된 슬롯 데이터가 있다면 **자동 이전되지는 않습니다**. 기존 슬롯 데이터 이전 작업이 별도로 필요합니다.
- 디스호스트의 저장소가 재배포/재시작 시 초기화되지 않도록 영구 저장 기능을 확인하고 `data.db`를 주기적으로 백업하세요.
- 슬롯 슬래시 명령은 `config.json`의 `guildId`에 서버 전용으로, 자판기 명령은 글로벌로 등록됩니다. Discord에 반영되는 시간에 차이가 있을 수 있습니다.
- `TOKEN`과 지갑/DB 비밀번호를 GitHub에 공개하지 마세요. Litecoin 개인키/시드 문구는 입력하지 마세요.
- **실제 LTC 결제 전에 소액으로 입금 검증·채널 생성·재시작·만료를 테스트하세요.**

## 주의
슬롯 모듈은 `ENABLE_SLOTS=true`로 켠 서버에서만 작동합니다. **프리미엄 라이센스**가 있어야 슬롯 명령 및 결제를 사용할 수 있습니다. 슬롯 구매자의 LTC 결제는 서버 프리미엄 라이센스 구매와 별개입니다. 봇에는 채널 관리, 메시지 보내기, @here 멘션 등에 필요한 Discord 권한이 있어야 합니다.

재고 추가 로그에는 상품 가격(원), 추가 수량, 추가 후 재고, 추가 관리자 및 시각이 표시됩니다.

## 디스호스트 배포 (SQLite 통합 버전)
1. ZIP을 압축 해제한 뒤 **폴더 내부의 파일들**을 프로젝트 루트에 업로드합니다.
2. Node.js 20 이상, 시작 파일 `index.js`, 설치 명령 `npm install`, 실행 명령 `npm start`를 설정합니다.
3. `.env.example`을 `.env`로 복사해서 `TOKEN`, `MASTER_ID`, `ENABLE_SLOTS=true`, `DB_PATH=./data.db`를 설정합니다.
4. `config.example.json`을 `config.json`으로 복사해서 서버 ID, 관리자 역할 ID, LTC 수신 주소와 실제 카테고리 ID를 입력합니다.
5. 봇을 재시작합니다. **PostgreSQL / DATABASE_URL / PG_SSL 설정은 전혀 필요하지 않습니다.**
6. 디스호스트가 재설치 또는 재배포 시 작업 디렉터리의 SQLite 파일을 삭제하는지 반드시 확인하세요. 가능하면 영구 저장 디렉터리에 DB_PATH를 지정하고 정기적으로 백업하세요. `data.db`와 함께 `data.db-wal`, `data.db-shm`이 생길 수 있습니다. 실행 중 백업은 SQLite 백업 API 등 일관된 방식으로 하세요.

> 코드 문법 및 SQLite 핵심 SQL 동작은 검사했지만, 실제 Discord 로그인·Litecoin 실결제·디스호스트 환경 구동은 검증하지 않았습니다.


## 서버 설정 반영
`config.json`에 사용자 제공 서버 ID, LTC 지갑 주소, 슬롯 카테고리 ID를 입력했습니다. 일반/VIP 슬롯 모두 동일한 카테고리에 생성됩니다. `adminRoleIds`는 빈 배열이며 역할 기반 슬롯 관리자를 사용하려면 역할 ID를 넣으세요. `priceLtc`와 `durationDays`는 예시값이므로 운영 전에 실제 판매 조건으로 변경하세요.

## Unknown Guild (10004) 오류 처리

슬롯 기능만 대기하며, 동일한 봇을 슬롯 서버에 초대하면 명령어 등록을 다시 시도합니다.

## 재고 추가 로그 문구
- 자판기 `/관리` → **재고 로그 채널** 지정 → **재고 로그 문구**에서 제목과 본문 편집
- 치환 변수: `{상품}`, `{가격}`, `{추가수량}`, `{현재재고}`, `{관리자}`, `{시간}`

**운영 주의:** 봇이 슬롯 서버에 초대되어 있어야 패널 게시 및 결제가 동작합니다. 실결제 전 소액 테스트를 권장합니다.

## TXID 입력 오류 수정 (v1.3.1)

- `DiscordAPIError[10062]: Unknown interaction` 문제: `slot:txmodal:ko` / `slot:txmodal:en` 모달이 자판기와 슬롯의 두 이벤트 핸들러에서 동시에 처리되던 문제를 수정했습니다.
- 슬롯 모달은 슬롯 처리기에서만 처리합니다. `deferReply`가 만료되었거나 중복 응답일 때 프로세스가 종료되지 않도록 보호 코드를 추가했습니다.
- 블록체인 TXID 조회에 15초 타임아웃을 추가했습니다. 재시도 시에는 기존 주문의 TXID를 다시 입력할 수 있습니다.
- 배포할 때 **기존 `data.db`와 `config.json`을 백업하고 삭제하지 마세요.** 별도 `data.db-wal` / `data.db-shm` 파일이 있다면 실행 중 복사하지 말고 서버를 안전하게 정지한 뒤 백업하세요.

- 패널을 보는 **일반 사용자도** `🎨 티켓 스타일 직접 선택` 드롭다운에서 세 디자인 중 원하는 스타일을 선택할 수 있습니다.
- 선택 결과는 본인에게만 표시되며 `이 스타일로 티켓 열기`를 누르면 선택한 테마 색상으로 티켓 안내가 생성됩니다. 다른 사람의 패널은 변경되지 않습니다.
- 기본/선택 테마는 Discord 임베드 색상과 텍스트 스타일이며 AI 이미지 파일 생성 기능은 아닙니다.
- 일반 라이센스와 프리미엄 라이센스 모두 티켓 기능 사용 가능합니다.

## 슬롯 TXID 오류로 인한 종료 방지 (v1.4.2)
- TXID 검증 실패(금액 부족, 주소 불일치, 컨펌 부족, TXID 미조회 등)는 Discord 사용자에게 개인 오류 안내로 처리합니다. 실패한 결제를 성공으로 처리하지 않습니다.
- 슬롯 interaction 핸들러 최상위에 비동기 오류 보호를 적용했습니다. Discord 클라이언트 `error` 이벤트 및 처리되지 않은 Promise 거절은 로그에 남겨 종료 가능성을 줄입니다.
- 네트워크 장애·권한 오류 등 개별 작업 실패는 해당 요청에서 처리하며 자판기·티켓 기능은 계속 동작하도록 설계했습니다. 다만 모든 종류의 치명적인 Node.js 오류(메모리 부족, 강제 종료 등)까지 막을 수는 없습니다.
- 로그의 `내 LTC 수신 주소로 결제 금액 이상이 입금된 출력이 없습니다`는 해당 TXID의 **개별 출력(vout)** 중 `config.json`의 `ltcAddress`로 `expected_sats` 이상 송금된 항목이 없다는 의미입니다. 주소, 수량, 네트워크, TXID, 주문 유효시간을 확인하세요. 여러 출력의 합산은 현 검증 대상이 아닙니다.
- 배포 시 기존 `.env`, `data.db` 보존. `config.json`에는 운영 중인 LTC 수신 주소와 서버 정보가 있으니 기존 설정을 우선 유지하세요.


## v1.4.3 슬롯 구매자 역할 자동 지급 (디스호스트)
- 슬롯 서버에서 관리자 `/슬롯역할설정 역할:@구매자` 실행. 역할 미선택 시 현재 설정 조회, `해제:true`로 비활성화.
- LTC TXID 검증 및 슬롯 채널 생성 완료 뒤 구매자에게 지정 역할을 지급합니다. 기존 슬롯 연장 완료에도 역할을 확인하고, 재시작 시 기존 활성 슬롯 구매자에게 역할을 동기화합니다.
- 슬롯이 만료되거나 `/슬롯삭제`로 회수되면 **해당 사용자의 다른 활성 슬롯이 없을 경우에만** 역할을 회수합니다.
- 역할 지급/회수 실패 시 결제 완료 결과나 봇 가동을 중단하지 않고 서버 로그에 실패 원인을 기록합니다.
- 봇에 **역할 관리(Manage Roles)** 권한이 필요하며, Discord 서버 역할 설정에서 **봇 역할이 구매자 역할보다 위**에 있어야 합니다.
- 기존 `config.json`은 업로드시 백업하고 덮어쓰지 마세요. 신규 설정은 `/슬롯역할설정` 명령으로 파일에 저장합니다. 설정 저장 후에도 Discord 권한 상태를 확인하세요.
- 실제 Discord 권한 및 결제 동작은 운영 서버에서 테스트가 필요합니다.
